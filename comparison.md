I compared rules-based search, an LLM given the full policy database, and an LLM given the three policies retrieved through a Gemini vector index on the same ten questions, including paraphrases, missing information and a misleading instruction. Both LLM methods used gemini-3.5-flash-lite with identical instructions and a temperature of 0; the vector index used gemini-embedding-001. Average response times were 0.0007, 0.9869 and 1.2054 seconds, respectively, and average reported LLM token totals were 0, 3,741.8 and 298.7. The vector approach therefore used approximately 92% fewer LLM tokens than the full-database approach, but was slightly slower. Query and document embedding token counts were not reported by the API and are excluded from these LLM totals, so this is not a comparison of total token usage across all models. One-time index creation took 5.184 seconds and was excluded from per-question response times.

Manual review against the CSV found no invented policy claims in any method's ten answers (0/10 each), while rules-based search, the full-database LLM and the vector LLM correctly answered the question and identified the relevant policy in 8/10, 10/10 and 9/10 cases, respectively. Incorrect policy selection was assessed separately from invented claims: for example, rules-based search returned the unrelated Business Continuity Policy for the $700 expense question, while the vector LLM correctly acknowledged that pension contributions were unspecified but cited unrelated policies. My preferred approach for this small, 98-policy dataset is the LLM without a vector index because it achieved the highest correctness and was slightly faster than the vector approach. Its main tradeoff is substantially higher LLM token use because it receives the entire database for every question. These findings describe a small, single-run test set; network conditions, model variation and retrieval errors can affect the results, so they do not establish that one method is always best or that unsupported answers will never occur.
